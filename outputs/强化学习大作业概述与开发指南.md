# 强化学习游戏智能体大作业：任务书与开发指南

> 适用课程：研究生《Reinforcement Learning》课程项目考核  
> 组织形式：3–5 人一组，8 周完成  
> 计算条件：个人电脑（可配备 RTX 5070 Ti 同等级 GPU）或课程 DGX 平台  
> 作业结构：必做一：单蛇 DQN＋双蛇自博弈；必做二：马里奥视觉 RL；附加题：Minecraft  
> 文档版本：2.0，2026-09-09（八周版）

本作业要求小组构建能够通过环境交互改善策略的游戏智能体，并用可复现的实验说明：模型学习了什么、为什么有效、在哪些条件下失效。考核重点是强化学习知识的掌握与运用，包括问题建模、算法实现、奖励设计、探索、长期决策、多智能体博弈与实验分析。

本文中的“必须”属于提交要求，“建议”提供开发起点，“挑战”属于提高项目质量的可选成果。所有奖励系数、超参数和资源预算示例均为教学设计，不代表已经运行验证的最优配置。本文未搭建游戏环境、运行训练或产生实验成绩；环境介绍依据文末官方文档与研究资料核查，学生须完成本机兼容性验证。

## 1. 课程目标与总体要求

### 1.1 完成后应能回答的问题

1. 游戏如何表示为序贯决策问题？哪些信息属于环境状态，哪些是智能体实际可见的观测？
2. 如何让智能体兼顾眼前收益和未来风险，而不是仅追求一步奖励？
3. DQN 如何从交互样本构造学习目标？目标网络、经验回放和探索分别解决什么问题？
4. 为什么训练回报提高不一定意味着游戏能力提高？如何发现奖励漏洞？
5. 模型是否只记住了训练地图或轨迹？如何用未见条件测试泛化？
6. 使用算法库、预训练模型或技能模块后，小组自己的强化学习贡献是什么？
7. 对手持续变化时如何训练和评估策略？自博弈胜率上升是否代表对所有对手都更强？
8. 如何自主提出科技树探索问题，并用真实实验解释成功、失败与资源取舍？

### 1.2 强化学习目标

可将完全可观测游戏建模为 MDP：状态集合、动作集合、转移规律、奖励函数、折扣因子和初始状态分布。智能体以策略选择动作，通过交互优化期望折扣累计回报：

$$
J(\pi)=\mathbb{E}_{\pi}\left[\sum_{t=0}^{T-1}\gamma^t r_{t+1}\right],\qquad 0\leq\gamma<1.
$$

其中，策略与环境随机性共同决定轨迹，$T$ 为任务轨迹长度。较大的折扣因子通常让更远期的奖励进入决策，但也可能增加估计和探索难度。应结合决策频率解释折扣范围；例如 $\gamma^{1000}$ 在 $\gamma=0.99$ 时已很小，长任务不能只靠增大训练时长解决。

只有游戏画面时，单帧通常不能完整描述速度、遮挡物和历史行为，可按 POMDP 处理，使用帧堆叠、循环网络或记忆模块。不能把少量“前方有无危险”等人工特征直接称为完整状态。基础理论可参考 Sutton 与 Barto 教材，第 3、6、9、13 章分别对应建模、TD 学习、函数逼近和策略梯度，见第 8 节。

本作业中的“长期最优”指**以长期累计回报为优化目标，并在指定预算和测试条件下寻找表现更好的策略**。不要求证明在复杂游戏中达到全局最优。训练回报、游戏原生分数和任务成功率必须分别记录。

### 1.4 开放探索与创新实践

鼓励学生在明确目标和资源约束下自主提出问题、探索多种解决路径。通过黄金器、钻石器等自主支线，拓展对游戏机制和智能体能力的认识，培养勇于创新、理性试错、协作攻关和实事求是的研究态度。探索的价值体现在问题意识、学习过程与反思质量，不以额外分数或装备数量衡量。

将这一育人目标落实为“提出假设—团队讨论—实施实验—保留失败—反思改进”。自主支线不成为隐性必做内容，不按支线数量评分。尝试无效时也应保留证据并解释原因；不能为展示创新而夸大模型能力或掩盖失败。

## 2. 三款游戏任务卡

### 2.1 必做一：贪吃蛇——单蛇学习与双蛇自博弈

#### A. 单蛇环境与规则

建议自行实现游戏逻辑并封装为 Gymnasium 环境，渲染与逻辑解耦。可复用开源游戏逻辑，但须引用并核对规则。Gymnasium 自定义环境接口见[官方教程](https://gymnasium.farama.org/introduction/create_custom_env/)。

以下配置为基础评测协议，小组可增加其他设置，但不得用不同规则替换基础结果：

| 项目 | 基础协议 |
| --- | --- |
| 棋盘 | 10 × 10，无障碍、不穿墙 |
| 初始蛇 | 长度 3，水平居中，蛇头朝右；以从 0 开始的 `(行, 列)` 记为头 `(5,5)`、身体 `(5,4)`、尾 `(5,3)` |
| 食物 | 每次在空格中均匀随机生成，随机源由环境种子控制 |
| 动作 | 三个相对动作：直行、左转、右转；每次动作前进一格，不设置直接反向动作 |
| 成长 | 吃到一个食物增长一格，并在仍有空格时生成下一个食物 |
| 碰撞 | 撞墙或撞身体结束；未进食时尾部同步移走，因此允许进入本步腾出的尾格 |
| 满盘 | 长度达到 100 为任务成功，立即结束，不再生成食物 |
| 外部预算 | 每局最多 2,000 个动作；达到上限为时间截断，不额外添加“饥饿死亡”规则 |

**默认观测采用完整棋盘状态。**推荐用“有序蛇身地图 + 食物地图 + 朝向”表示：蛇身地图中空格为 0，蛇头到蛇尾依次填入 `1/100, 2/100, …, L/100`，食物单独一张二值图，朝向用四维 one-hot 表示。可以直接展平送入 MLP，也可以使用 CNN。只使用身体占用二值图可能丢失身体顺序；采用压缩表示时应明确其信息损失，不再声称完整可观测。

#### 奖励与指标

基础 DQN 使用以下教学奖励，改进方法可调整塑形项：每步 `-0.001`，吃食物加 `+1`，碰撞加 `-1`，满盘额外加 `+10`。事件项与步成本相加；满盘最后一次进食仍有食物奖励；时间截断没有额外失败奖励。所有奖励分量应分列日志。

实际成绩以**每局食物数**为主要指标，另报告最终长度、棋盘占用率 `最终长度 / 100`、存活步数、碰撞率、满盘成功次数与截断率。不要只用存活时间评分，原地循环可能延长寿命却没有改善觅食能力。

#### 基础实验与挑战

必须实现四组方法：

1. 随机策略：在三个相对动作中均匀采样，不额外屏蔽危险动作。
2. 简单启发式：排除本步立即碰撞的动作，在剩余动作中选择到当前食物曼哈顿距离最小者；并列按直行、左转、右转选择；若均危险则直行。只能使用同一观测恢复的信息。
3. 手写 DQN：使用基础奖励、统一观测和动作空间。
4. 至少一项改进：建议先选 Double DQN，或明确提出的奖励/探索/表示改进；保持其他条件不变以解释贡献。

建议额外比较完整棋盘编码与相对危险/食物特征，说明信息损失；该实验可作为一项改进对照。

基础学习目标是在独立测试食物序列上取得可复现的学习增益。超过启发式策略属于更强的成果，不以“单次最好分数”判定达成。可以扩展到带障碍或不同尺寸地图，但须分别报告，尺寸变化时说明网络如何处理输入变化。

常见失败包括：食物出现在蛇身；尾格碰撞判断错误；满盘后生成食物死循环；训练时屏蔽危险动作而对照不屏蔽；智能体循环求生；奖励增长但食物数不升。先验证规则，再调整模型规模。

#### B. 双蛇对抗环境与统一规则

双蛇不是把两个单蛇循环依次运行。应建模为双方同时决策的随机博弈：各自收到同一步观测，提交动作，再由环境统一更新。学习难点包括对手变化造成的非平稳性、竞争目标、历史策略遗忘和策略循环。

| 项目 | 双蛇基础评测协议 |
| --- | --- |
| 棋盘与出生 | 15×15，无障碍、不穿墙；蛇 A 头/身/尾为 `(7,3),(7,2),(7,1)` 朝右；蛇 B 为 `(7,11),(7,12),(7,13)` 朝左；坐标从 0 开始 |
| 食物 | 初始在空格均匀生成 3 个不重叠食物；每步结算后从剩余空格均匀补足，空格不足时有多少补多少 |
| 动作 | 直行、左转、右转，各前进一步；双方同步提交，不显示对手本步动作 |
| 观测 | 自身有序蛇身图、对手有序蛇身图、食物图、双方朝向、双方累计食物数、归一化剩余时间；身体序号除以 225 |
| 生长 | 仅本步存活且成功占据食物格的蛇吃食物、增长一格，累计食物数加 1 |
| 对局上限 | 1,000 个联合环境步；每步双方各行动一次 |
| 胜负 | 一方死亡则另一方胜；同一步双方死亡为平局；到时双方存活则食物数多者胜，同分平局 |

**同步结算顺序必须一致：**

1. 根据步前状态分别计算转向后的候选头格，尚不改动棋盘。
2. 候选头格存在食物则标记“拟进食”。构造每条蛇本步的碰撞占用集合：拟进食保留原身体全部格子，否则去掉原尾格；集合包含原头格。
3. 各自候选头撞墙或落入上述任一占用集合则标记死亡；双方候选头落同格时均死亡，双方交换原头位置时也均死亡，与长度无关。
4. 使用同一批标记统一结算。去掉的尾格本步视为可进入，即使该蛇在其他位置死亡也不回滚；这是本课程的同步移动约定。只有存活者实际增长和获得食物，同格争食双方死亡则不获得食物。
5. 若有人死亡，先按存活情况结束对局；否则更新双方身体、补足食物，再检查 1,000 步时限。死亡胜负优先于食物比较。

食物补充不得在无空格时死循环。双方未死亡而占满棋盘时允许食物数不足，继续到死亡或规定时限。本协议不引入“蛇越长，头碰头必胜”等另一套规则。

1,000 步是决定胜负的任务时限，因此达到时限对双方均为 `terminated=True`，没有后续价值 bootstrap。剩余时间作为观测使有限时域目标可被表示。正常结束时两条蛇都终止，包括获胜方；额外技术中断应单列，不能当作正常失败转移。

#### 双蛇奖励、基线与评价

先以胜 `+1`、负 `-1`、平 `0` 的终局奖励建立基线。为缓解稀疏奖励，可尝试每步增加 `0.05 ×（本方本步食物数 − 对方本步食物数）`，双方对称取值；仍以真实胜平负评价，塑形版本与纯终局版本分开标注。不得仅奖励长时间存活而忽略竞争目标。

固定对手定义如下，所有对手都只能读取同一权限的观测：

- **随机对手：**在三个动作中均匀采样，不加动作屏蔽。
- **启发式对手：**将对方当前整条身体视为障碍；自身尾格在候选不进食时可腾空；排除撞墙和上述已知障碍的动作。选择到最近食物曼哈顿距离最小的候选，同分按直行、左转、右转，无候选则直行。它不预测对手本步动作，也不能保证避开移动中的对手。
- **冻结学习对手：**来自其他独立训练种子的最终模型，模型之间在训练、调参和验证期间不互相暴露；测试时统一冻结。

至少训练一个带历史对手池的自博弈方案，提供固定对手训练或“仅最新快照、不用历史池”的受控对照。建议以最近快照为起点，逐步加入历史对手，方法细节见第 3.6 节。

报告每个对手与双方座位上的胜/平/负、食物数、对局长度、碰撞原因，以及 `胜率 = 胜局 / 总局数` 和 `对局得分率 =（胜局 + 0.5×平局）/ 总局数`。后者用于统一选模，不能与胜率混称。历史对手上的表现用于分析遗忘；对其他训练种子模型的表现用于分析未见对手泛化。

四蛇、联盟训练和合作包夹是选做拓展，必须另外定义博弈目标和接口。双蛇纯竞争任务不要求信用分配式合作算法，也不以观察到一次“包夹”就断言学会合作。

### 2.2 必做二：马里奥——二维视觉输入下的深度 RL 全流程

#### 环境与信息权限

优先考察 [`gym-super-mario-bros` 与 `nes-py`](https://github.com/Kautenja/gym-super-mario-bros)。当前仓库文档采用 Gymnasium 接口，而历史版本和教程可能使用旧 Gym；须按实际安装版本核对 Python、原生模拟器和 API，不能混用不同版本示例。

| 项目 | 课程路线默认设置 |
| --- | --- |
| 游戏与训练关卡 | 原版 Super Mario Bros.，单关 `1-1`；具体环境 ID 与 ROM 模式写入配置 |
| 策略观测 | 游戏图像；建议灰度、84 × 84、最近 4 帧堆叠作为起点 |
| 策略动作 | 固定离散按键组合，建议采用所选版本的 `SIMPLE_MOVEMENT`，保存完整动作映射 |
| 辅助信息 | 位置、死亡和过关事件只用于奖励与评测；不能将模拟器内部坐标或关卡地图偷偷输入视觉策略 |
| 动作重复 | 建议每次决策最多执行 4 个底层帧，遇到终止立即停止；只设置一层重复，记录实际底层帧数 |
| 一局定义 | 单关单命，从规定起点开始；死亡或过关为终止 |
| 外部预算 | 每局最多 4,500 次智能体决策，达到上限为截断；游戏自身超时死亡属于终止 |

短跳、长跳和加速可能依赖按键持续时间，动作重复过长会跳过决策时机。缩放后应检查坑洞与角色是否仍清楚。基础图像转换须对所有方法一致，不能在测试中改变堆帧或归一化。

#### 奖励与任务成绩

建议先使用安装版本的原始环境奖励并记录其精确定义，再进行一次奖励改进。自定义奖励示例为：

$$
r_{t+1}=\alpha\max(0,x_{t+1}-x_{\max,t})-c+\beta I_{\text{clear}}-\delta I_{\text{death}}.
$$

其中 $x_{\max,t}$ 为本局此前最远位置；新位置奖励用于减少左右往返刷分，$c$ 为步成本。该示例依赖历史最大位置，必须由包装器维护，并说明它使奖励具有历史依赖；不能宣称这种改动必然保持原任务最优策略。位置变化只在同一连续关卡坐标系中计算，过关转场或坐标重置不得产生虚假大额奖励。

主要指标为单关通关率和每局最远推进距离。另报告原生分数、死亡率、截断率、成功局用时及交互预算。若报告归一化距离，必须定义起点和终点坐标，不能简单跨不同关卡比较未经校准的横坐标。

#### 基础实验与挑战

必须提交随机策略、训练所得 RL 基线、最终改进方案以及至少两项消融，并自主实现或实质改造一个奖励包装器、课程调度器、策略网络等模块。建议基线采用 PPO + CNN；也可使用 DQN 系列。单关目标是通过学习提高推进距离，并尽力获得稳定通关；完成训练与分析是基础要求，通关能力影响效果评分，不要求所有未见关卡都通关，也不设“未通关 1-1 则整题不及格”的单一门槛。原版世界 1 包含 1-1 至 1-4 四关；多关成绩须说明是逐关独立通过还是连续通过。

基础泛化协议：`1-1` 用于训练和同关验证；`1-2` 与 `1-3` 保留为最终未见关卡测试。测试使用冻结策略。默认每局在初始状态执行无操作等待：训练从 `0–19` 帧中采样，验证逐一使用 `20–39` 帧，最终测试逐一使用 `40–59` 帧；每个测试关卡的 20 局各覆盖一个测试等待长度。须检查该扰动在所选版本中是否真的改变状态。这种划分增加同关起点多样性，并引入轻微起始时间变化，不能替代跨关卡泛化。

确定性环境中，仅改变一个未被使用的随机种子可能产生完全相同的轨迹。必须记录起始等待、策略是否随机和实际轨迹差异；若轨迹仍重复，如实报告，不能把重复 20 次称为 20 个独立世界。跨关测试可以零成功，仍需报告失败位置及原因。

挑战可采用多关课程学习或未见关卡少样本微调。若要把 `1-2` 或 `1-3` 用作训练或验证，应在首次训练前另行登记不重合的测试关卡。零样本测试与微调后成绩必须分表；微调使用的交互计入预算，原测试关卡一旦参与训练就不再属于未见测试。

常见失败包括：卡住却持续获得奖励；只会一直向右跑；跳跃时机因跳帧丢失；以内部坐标辅助决策却声称纯视觉；将选出的通关录像当成平均水平；在测试关卡上反复调参。

### 2.3 附加题：Minecraft——基础技能与开放科技树挑战

#### 目标、环境与信息权限

最终目标是自主进入**末地（The End）并击败末影龙（Ender Dragon）**。Minecraft 是自愿附加题，以三维世界视觉、部分可观测性和科技树长链为研究对象，按 P1/P2 两个基础前置阶段与 T1–T7 七个后续阶段验收，最高附加 20 分。完成基础阶段即可取得对应分数，不要求先完成整条链路。应先保障两款必做项目，再按余力探索。

| 环境候选 | 适合用途 | 采用前必须核查 |
| --- | --- | --- |
| [MineRL](https://github.com/minerllabs/minerl) | 游戏交互、示范或预训练路线 | 所选版本的观测、动作、任务列表、Java/显示依赖与 Gym 接口；旧版与 1.x 差异 |
| [MineDojo](https://docs.minedojo.org/) | 自定义初始条件、采集/战斗任务、开放探索 | 游戏版本、成功事件、结构化观测、世界重置和服务器资源 |

MineDojo 基准包含“Playthrough: Defeat the Ender Dragon”；存在任务不等于提供了能完成它的策略，也不是课堂预算可从零训练通关的保证。[任务说明](https://docs.minedojo.org/sections/core_api/sim.html)

建议先尝试便于定义子任务的 MineDojo；已有兼容预训练模型可采用 MineRL。选择附加题后，先验证单实例能够观测、行动、重置、记录事件，再启动训练。不同 Minecraft 版本和后端单列结果，不能假设预训练动作接口直接兼容。

允许图像与已声明的血量、背包、朝向、目标等结构化观测。目标坐标、体素、射线和实体位置须列出范围，让对应对照具有相同权限。图像、混合输入和完全结构化输入分组标注；完全结构化策略不能声称证明了三维视觉控制能力。评测可用服务端真值，但须与策略输入隔离。

动作可采用按键与离散视角增量或有限技能。复用脚本技能、预训练权重或大模型规划必须注明来源；计分阶段须有作用于该阶段的 RL 更新及其贡献对照，不能仅因别的阶段训练过，就把后续纯脚本能力归因于 RL。学习低层技能或学习技能选择策略均可，但须明确优化对象、奖励与无 RL 对照。

评估开始后不得人工接管或用管理指令完成目标。课程存档、预置装备和初始化命令须事前登记；运行中干预单列，不计入自主成功。可使用声明过的记忆机制和高层规划，但冻结模型参数并记录外部调用成本。

#### 九阶段任务与验收事件

| 阶段 | 目标与可核对事件 | 满分 |
| --- | --- | ---: |
| P1 导航与生存 | 从规定出生区域自主到达目标区域并保持存活；默认活着进入距目标树不超过 2 格的可站立位置 | 1 |

P1、P2 分别提供实际 RL 训练、未学习对照和独立场景评测，可以使用独立策略或共享条件策略。两者可以分开验收；获得 P1/P2 分数不强制要求连续组合演示。若报告组合成功，阶段间不得重置世界、补充背包或传送。

P1/P2 正常初始化建议为正常生存难度、白天、空背包、附近有可达树木；P1 目标坐标如可见须声明，P2 可从距目标树 2 格内启动。P1 必须从目标区域外开始，P2 不预置目标原木。改变出生位置、树种、地形和世界种子进行独立评测；筛选世界只依据事前地形条件，不按模型能否成功筛选。

P1 建议外部上限 1,000 次决策，P2 为 2,000 次，连续组合为 3,000 次；动作重复最多 4 个游戏 tick。后续阶段按吞吐登记预算，所有对应对照一致，同时记录决策、tick 与墙钟时间。这些是任务设计起点，不代表已验证可达。

#### T3 起开放科技树与自主支线

T3 的铁器路线是教学示例，不是唯一攻略。学生可以选择黄金器、钻石器，并探索附魔、酿造、资源储备或其他合理支线。登记“希望解决的任务—资源获取—必要加工—装备制作—实际用途验证”；例如制作一件所选装备后，执行与其用途相符的采掘、防护或战斗操作，核对使用结果。不能只凭背包截图证明智能体完成了能力链。

选择不同材料仍只按 T3 同一阶段评分，最高 2 分。原矿需要的加工按游戏机制执行；已获得可用钻石的路线不强制冶炼。比较工具适用范围、获取成本、耐久和后续任务需求，不把材料排列成简单单调升级序列。合法取得前置工具、燃料或其他材料的过程须保留记录；若由课程直接提供，按辅助起点评分。

T4–T7 保留核心目标，但不限定装备组合、技能调度或唯一实现路径。例如建立传送门可使用所选版本支持的合法采掘或浇筑方式。自由支线不能代替烈焰棒、末影之眼或实际击败末影龙等核心事件。

**自主支线、额外装备、重复制作不新增阶段分、不重复计分，也不形成隐性必做要求。**已经取得 T3 全分，再做黄金器、钻石器或附魔不再加分；不完成这些支线不扣分，不以支线数量决定任何评分项。鼓励用第 6.5 节的自主探索记录展示动机、策略假设、学习方法、成本、结果与反思，失败探索也可以展示。

这一安排将开放探索与创新实践落实到具体活动：自主提出问题，比较多条路径，团队协作试验，尊重实际证据，并理性解释失败。重点是拓展视野、勇于创新和实事求是，不是为了加分制作更多装备。

#### 辅助档、完整档与计分边界

| 阶段类别 | 正常或完整档 | 辅助档 | 不计分情形 |
| --- | --- | --- | --- |
| P1、P2 | 正常任务初始化、完成核心能力及学习评测证据，各得 1 分 | 提供缩短关键能力链的帮助，但仍有实际学习和有效子目标，各最多 0.5 分 | 出生即满足目标、直接给予目标原木、未展示作用于本阶段的 RL |
| T1–T7 | 从新世界自主完成前序链条，或恢复自身策略生成且前序证据连续的存档，完成本阶段可得该阶段 100% | 预置前置资源或课程存档，从声明起点独立完成本阶段可得该阶段 50% | 核心目标未完成、目标物品直接给予、只运行脚本/未微调模型而无 RL 贡献 |

正常任务初始化本身不自动减分。例如 P2 本来研究近距离采集，从树附近开始符合完整的 P2 任务；直接提供四个原木则跳过其核心能力，不得分。辅助条件须在训练和验收前登记，不能见到结果后改写任务。

T1–T7 完整档需证明此前 P1/P2 与各 T 阶段的核心事件在自主链条中发生；可在多个可追溯、自主生成的阶段存档间恢复，但不得补物资、改世界或跳过未完成前序。恢复记录不自动等于“单次无中断完整通关”，两者分开报告。自主链条中的实际事件可同时作为相应前序阶段证据，但仍须满足各阶段学习与评测要求。

各阶段独立登记、只取最高档，不把辅助档与完整档相加，也不为同阶段不同材料支线重复计分。辅助起点不能获得被跳过阶段的分数。T3 的替代材料路线满足同一能力链即可，无须另做铁器；后续所需的其他前置材料仍须按实际机制取得或披露辅助来源。

申请某一档位须提供目标完成事件、完整对应轨迹、代码/模型、RL 对照和规定的多种子评测；展示每个种子的成功次数与失败原因，不以一条成功录像替代全部评测。仅运行评测但始终未完成目标不算该阶段完成；完整档与辅助档均不把“提交了材料”自动视为成功。证据不足的进展作为个案记录，待补齐再验收，不设未经验证的绝对成功率门槛。

#### 奖励与结果报告

采集与科技树奖励可按物品数量阈值或制作事件首次达成发放，避免丢弃再拾取、重复合成或拆解刷分。T3 不应因制作材料更多而无限增加训练奖励；可围绕本次登记的装备用途奖励。导航可用势函数塑形，探索可用首次到访区域奖励，但须检查是否只在游荡而没有推进核心目标。

至少分四类报告，未尝试项填写“未尝试”：单阶段、无重置连续组合、辅助起点挑战、新世界完整流程。记录世界种子、起点、装备、观测权限、预算、各阶段到达与成功次数、死亡、截断、时间及干预。全流程阶段到达率以全部启动尝试为分母，不删除未到达后期的失败。

常见失败包括：存活奖励诱发躲藏；重复访问刷探索奖励；子任务成功但衔接失败；装备用途与任务需求不匹配；预训练接口不兼容；将预置装备的末地战斗标为从零通关。应将这些情况作为问题诊断与反思材料。

## 3. 算法路线与关键原理

### 3.1 贪吃蛇必须掌握的 DQN

以 $Q_\theta(s,a)$ 估计动作价值，目标网络参数为 $\theta^-$。从经验池采样转移 $(s,a,r,s',d)$，其中 $d$ **只表示真正终止**。本节 $r$ 为该次转移奖励，$s$ 在完全可观测贪吃蛇中是状态，在视觉路线中可替换为观测历史表示。

$$
y=r+\gamma(1-d)\max_{a'}Q_{\theta^-}(s',a'),
\qquad
L(\theta)=\frac{1}{B}\sum_{i=1}^{B}\operatorname{Huber}(Q_\theta(s_i,a_i)-y_i).
$$

计算目标 $y$ 时停止梯度；仅更新在线网络，再按周期复制到目标网络。经验回放用于复用样本并降低相邻轨迹样本的相关性，目标网络减缓学习目标快速变化。它们不能保证收敛，也不能弥补错误奖励或观测不足。DQN 经典来源见第 8 节 DQN 文献。

以下是**单环境、无自动重置包装器**的逻辑伪代码，学生需自行实现，不是可直接执行的库调用：

```text
设置网络初始化、环境、探索与回放采样的随机种子
初始化在线 Q 网络，复制得到目标 Q 网络；创建优化器和经验池
s = env.reset(seed=训练种子).observation
for t in 1 ... 总交互预算:
    epsilon = 探索日程(t)
    a = 以 epsilon 概率随机动作，否则 argmax_a Q_online(s, a)
    s_next, r, terminated, truncated, info = env.step(a)
    保存 (s, a, r, s_next, terminated, truncated) 到经验池

    if 经验池达到预热数量 and 到达更新间隔:
        随机采样一批转移
        在 no_grad 下计算 y = r + gamma * (1 - terminated) * max Q_target(s_next)
        loss = Huber(Q_online(s, a), y).mean()
        optimizer.zero_grad()
        loss.backward()
        裁剪梯度范数
        optimizer.step()

    if 到达目标网络同步周期:
        Q_target <- Q_online
    if 到达验证周期:
        在独立验证环境评估；按预定验证指标保存最佳模型
    if terminated or truncated:
        s = env.reset().observation
    else:
        s = s_next
保存末次训练状态与完整日志
```

外部时间截断时，状态本来还能继续，因此仍应 bootstrap；若任务定义本身就是“有限时间内完成”，应将剩余时间纳入状态并按真正任务终止建模。单蛇、马里奥和 MC 默认训练步数上限采用外部截断；双蛇的 1,000 步比赛时限属于任务本身，按真正终止处理。带自动重置的向量环境须保存截断前最终观测，不能将下一局初始观测当作 $s'$。

**贪吃蛇 DQN 起始配置（教学建议，须通过验证集调整）：**

| 配置 | 起点值 | 解释 |
| --- | --- | --- |
| 网络 | 展平观测 → 128 → 128 → 3，隐藏层 ReLU | 先建立小网络基线 |
| 优化器与学习率 | Adam，`1e-3` | 观察 TD 误差与梯度，必要时降低 |
| 折扣因子 | `0.99` | 与游戏决策步一致 |
| 经验池与 batch | 50,000 条，64 条/批 | 按实际观测大小估算内存 |
| 预热与更新 | 1,000 条后开始，每 4 个环境步更新一次 | 先收集一定状态多样性 |
| 目标网络 | 每 1,000 个环境步硬同步 | 不与梯度更新次数混淆 |
| 探索 | epsilon 从 1.0 在前 100,000 步线性降到 0.05 | 后续保持 0.05；测试时为 0 |
| 初始训练预算 | 每个训练种子 300,000 个环境步 | 先跑短实验验证，不是达标保证 |
| 验证 | 每 10,000 步，在固定 20 个验证种子上评估 | 按平均食物数选模型，同分取较早模型 |
| 梯度裁剪 | 最大范数 10 | 记录梯度，不能用裁剪掩盖实现错误 |

### 3.2 Double DQN 与其他改进

Double DQN 使用在线网络选择下一动作，再由目标网络估计其价值：

$$
a^*=\arg\max_{a'}Q_\theta(s',a'),\qquad
y=r+\gamma(1-d)Q_{\theta^-}(s',a^*).
$$

它针对最大化操作可能带来的价值高估，是贪吃蛇较容易隔离验证的一项改进。保持网络、奖励、预算和种子一致，比较 DQN 与 Double DQN；不要为了获得更好结果同时更改多项设置。[论文](https://arxiv.org/abs/1509.06461)

也可探索 dueling 架构、优先经验回放、n-step return 或不同探索日程。一次实验先改变一个主要因素，解释假设与代价。不能仅增加训练步数就声称算法改进有效。

### 3.3 PPO：马里奥与复杂策略的可选起点

PPO 通过当前策略采样，再进行多轮小批量优化。其裁剪代理目标为：

$$
L^{\mathrm{clip}}(\theta)=\mathbb{E}_t\left[\min\left(\rho_t(\theta)\hat A_t,
\operatorname{clip}(\rho_t(\theta),1-\epsilon_c,1+\epsilon_c)\hat A_t\right)\right],
\quad
\rho_t(\theta)=\frac{\pi_\theta(a_t\mid o_t)}{\pi_{\mathrm{old}}(a_t\mid o_t)}.
$$

上式是最大化目标；实现最小化损失时取相应负号，再加入价值损失和熵项。学生须解释优势估计、旧策略概率、裁剪和熵系数的作用，并记录近似 KL、熵、价值损失与成功率。与 DQN 的长期经验池不同，标准 PPO 依赖当前一轮采样数据，不能无条件反复使用任意旧轨迹。[PPO 原论文](https://arxiv.org/abs/1707.06347)

双蛇、马里奥和 MC 可采用 Stable-Baselines3 的 PPO 或参考 CleanRL；使用库仍需说明策略网络、采样长度、并行环境数、batch、更新轮数与终止处理。DQN 通常用于单一离散动作空间；Minecraft 的组合动作需做适配，不能将默认 DQN 直接用于任意字典动作空间。

### 3.4 奖励塑形与探索

先区分环境任务奖励与训练辅助奖励。势函数塑形采用：

$$
r'_{t+1}=r_{t+1}+\lambda\bigl(\gamma\Phi(s_{t+1})-\Phi(s_t)\bigr).
$$

在满足相应 MDP、折扣与边界条件时，该形式具有保持最优策略的理论依据；有限回合需一致处理终止势，真正终止状态可设势为 0，外部截断不能直接当作真正终止。直接加“离食物越近奖励越大”不自动具有同样保证。[原论文](https://ai.stanford.edu/~ang/papers/shaping-icml99.pdf)

贪吃蛇可试用头到食物的负距离作为势，但需要完整状态并处理食物重生。Minecraft 可用阶段目标进度，前提是目标与已完成事件纳入定义。所有塑形方案至少检查循环、重复拾取、拖延结束和捷径行为。探索可从 epsilon-greedy、熵正则或课程随机化开始，再考虑新颖度等机制。

### 3.5 课程学习、分层强化学习与预训练

| 方法 | 适用情形 | 必须说明的实验问题 |
| --- | --- | --- |
| 课程学习 | 马里奥由简单片段到完整关卡；Minecraft 从邻近目标到远距离目标 | 相同总交互下是否优于直接训练？课程切换条件是否只依赖训练/验证？ |
| 分层强化学习 | 长目标可拆成导航、采集、合成、战斗 | 哪些技能是学习所得？高层是脚本还是 RL？失败如何交还控制？ |
| 示范 / 模仿预训练后 RL | 从零探索几乎无法触发有效奖励 | 同一起始权重下，RL 微调相较未微调模型改善了什么？ |
| 预训练视觉策略 | 需要低层视觉和动作先验 | 版本、观测、动作、权重许可和冻结范围是否匹配？ |
| 大模型辅助规划 | Minecraft 自动生成阶段目标或调用技能 | 大模型与 RL 各做什么？移除 RL 后是否仍取得同样结果？ |

对执行 $k$ 个底层步的技能，高层回报应按 $R=\sum_{i=0}^{k-1}\gamma^i r_{t+i+1}$ 累积，后续价值用 $\gamma^k$ 折扣；若把每个技能调用重新定义为固定一步目标，必须说明目标含义发生了变化。技能终止、全局任务终止与超时需分别记录。Options 框架为这种时间抽象提供理论基础，见第 8 节。

VPT 可作为视觉行为预训练研究参考，但复用权重不等于完成自己的 RL 训练，公开仓库也不应被假定为开箱即用的末影龙训练管线。[VPT 仓库](https://github.com/openai/Video-Pre-Training)

Voyager 提供自动课程与技能库的思路，其方法依赖大模型提示与代码技能，并不依赖模型参数微调。可以借鉴系统设计或用作对照，不能直接运行后将结果全部归因于强化学习。[Voyager 项目](https://voyager.minedojo.org/)

### 3.6 自博弈与历史对手池

自博弈是一种产生训练对手与交互数据的方式，不是替代 DQN/PPO 的独立优化公式。默认采用“当前学习者对冻结对手”：每局只更新学习者，局内对手参数不变，随机交换座位。先实现独立 DQN/PPO，再加入对手池，避免同时改动过多机制。

教学起点：保存随机初始化策略作为首个快照，每 20,000 个联合环境步在回合边界保存一次快照；保留最近 10 个历史快照及初始快照。每局以 50% 概率选最新快照，50% 从更早快照中均匀采样；没有更早快照时使用最新快照。频率、容量和采样比例可通过验证调整并记录。单蛇输入与双蛇不同，不能直接声称复制权重即完成迁移，须说明网络与观测适配。

```text
初始化学习者及其 DQN/PPO 状态
冻结初始模型，加入历史池；固定独立验证对手
while 联合环境步预算未用尽:
    选择本局冻结对手与学习者座位
    obs = 双蛇环境.reset(训练世界种子)
    重置双方回合记忆
    while 对局未结束:
        learner_action = 学习者根据本方观测选择动作
        opponent_action = 冻结对手根据对方观测选择动作（不更新参数）
        同时提交双方动作，统一结算并获得双方转移
        只保存学习者转移，附 opponent_id 与座位
        按 DQN 或 PPO 对应采样/更新规则优化学习者
        累加 1 个联合环境步，另记录双方动作总数
    若跨过快照间隔，在回合边界保存不可变快照并更新池
    到达验证周期时，对固定验证对手和验证种子评测
按验证对局得分率选择最终模型，冻结后进行正式测试
```

对手快照必须深拷贝参数并切换推理模式，不能与在线网络共享可变权重。循环策略还需每局重置记忆。记录池中版本、采样频率及每场实际对手；验证对手固定且不随学习者升级，以免胜率曲线的参照物一直变化。

DQN 回放中混合不同对手会增加非平稳性，应记录样本对手版本，分析是否需要限制样本年龄或按版本采样；PPO 保持当前 rollout 与旧策略概率一致。动作屏蔽若采用，必须在行为选择、训练目标和评测中一致，而且不能读取对手当前动作。

至少做一项对手机制对照，例如历史池与仅最新快照。比较相同联合环境步预算下的固定对手表现、跨种子对手表现和历史对手遗忘。允许报告 A 胜 B、B 胜 C、C 胜 A 的循环，不能据单个胜率断言存在绝对最强策略。相关流程可参考 [PettingZoo 自博弈教程](https://pettingzoo.farama.org/tutorials/agilerl/DQN/)，其中轮流行动游戏的例子不能原样代替本作业同步规则。

QMIX 和常见 MAPPO 研究主要面向合作多智能体问题；本作业纯竞争双蛇以独立学习和自博弈起步，不要求直接套用它们。探索四蛇合作、团队奖励或集中训练时，再明确联合目标、critic 的信息权限与分散执行边界。[QMIX](https://arxiv.org/abs/1803.11485)、[MAPPO](https://arxiv.org/abs/2103.01955)

## 4. 工程实现与复现指南

### 4.1 最小工程结构

以下是建议由学生实现的项目结构，并非本文附带的已实现代码：

```text
project/
  README.md                 # 安装、训练、评估、演示入口
  requirements-lock.txt     # 实际验证后的依赖锁定结果
  configs/                  # 游戏、算法、奖励、预算、种子配置
  envs/                     # 游戏逻辑、后端适配、奖励/观测包装器
  agents/                   # 手写 DQN、双蛇/视觉策略与技能接口
  opponents/                # 对手池清单、不可变快照和固定基线
  self_play.py              # 同步对局采样与自博弈调度
  cross_evaluate.py         # 冻结策略交叉评测、座位交换
  train.py                  # 参数更新与验证
  evaluate.py               # 加载冻结模型，逐局输出原始记录
  demo.py                   # 有记录的自主运行与视频导出
  checks/                   # 规则、TD 目标、重置和保存恢复检查
  runs/                     # 配置快照、日志、种子与运行清单
  checkpoints/              # 最佳模型与可恢复训练状态
  reports/                  # 实验报告、图表和演示索引
```

建议统一提供如下命令形式；文件名和参数可不同，但 README 中须给出实际可运行命令：

```text
python train.py --config configs/snake_dqn.yaml --seed 0
python evaluate.py --checkpoint checkpoints/snake_best.pt --split test
python demo.py --checkpoint checkpoints/snake_best.pt --seed 10000
```

先用一个环境、一条训练路线跑通“重置 → 采样 → 更新 → 保存 → 加载 → 评估”，再扩展并行和高级方法。无需为不同游戏强行复用全部逻辑，但训练记录与评测输出应有共同格式。

### 4.2 环境接口与终止处理

单智能体环境建议采用：

```python
obs, info = env.reset(seed=seed)
next_obs, reward, terminated, truncated, info = env.step(action)
```

`reset` 返回初始观测与辅助信息，`step` 返回观测、标量奖励、真正终止、截断与辅助信息；观测/动作应符合声明的空间，`close` 释放资源。[Gymnasium API](https://gymnasium.farama.org/api/env/)

| 情形 | 重置环境？ | 基础 DQN 的 bootstrap？ |
| --- | --- | --- |
| 正常一步 | 否 | 是 |
| 真正死亡、任务成功、满盘 | 是 | 否 |
| 双蛇死亡判定结束或 1,000 步比赛时限 | 是，双方结束 | 否，属于有限时域任务终止 |
| 外部步数预算用尽 | 是 | 是，使用截断前最终观测 |
| 同一步同时终止和截断 | 是 | 否，真正终止优先 |
| 环境崩溃、服务器断连 | 重启并记异常 | 不构造虚假的正常学习转移 |

旧 Gym 四返回值 API 不能只把 `done` 改名为 `terminated`；需要依据原环境的时间上限信息恢复语义。向量环境和自动重置包装器保存最终观测的方式依版本而异，应阅读实际版本实现并做专项检查。[时间上限说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)

建议 `info` 中区分：`raw_score`、`reward_components`、`is_success`、`end_reason`、`stage_id`、`env_frames`。这些是项目自定义字段，不是所有库自动提供的标准字段。不得将评测真值经 `info` 无意泄露给受限观测策略。

**双蛇采用并行动作接口。**推荐按 [PettingZoo Parallel API](https://pettingzoo.farama.org/api/parallel/) 组织，同时返回以 agent ID 为键的字典：

```python
observations, infos = parallel_env.reset(seed=seed)
actions = {agent: policies[agent].act(observations[agent])
           for agent in parallel_env.agents}
observations, rewards, terminations, truncations, infos = parallel_env.step(actions)
```

包装器将冻结对手嵌入单智能体训练器时，仍须先获得双方动作再推进一次环境。联合步终止应传播给学习者，不能给获胜方留下虚假可继续状态。`parallel_api_test` 可检查接口，规则案例另行验证。

小组统一实现策略协议：`load(checkpoint, device)` 加载参数与配置；`reset_episode(seed, agent_id)` 清空回合记忆与 RNG；`act(observation)` 返回整数动作 0/1/2。这是本项目建议接口，不是库自带 API。双方策略实例只接收各自观测，评测禁用梯度和参数更新。非法动作或策略异常保留日志并记该方技术失败，另列异常率；不得静默替换成有利动作。

对手清单记录 `opponent_id`、来源训练种子、checkpoint 哈希、训练步数、生成时间和用途（训练/验证/最终测试）。观察范围、动作映射、身体编码和记忆重置方式应随模型一起保存。

### 4.3 必要检查与调试顺序

| 检查 | 必须观察到的行为 |
| --- | --- |
| 贪吃蛇规则 | 食物不占身体；吃食物增一格；碰撞正确；进入腾空尾格合法；满盘正确结束 |
| 双蛇同步规则 | 同格抢食/头部交换均同时死亡；正常腾空尾格可进入；交换 agent 字典顺序不改变结算 |
| 双蛇对称与时间 | 交换座位后规则一致；第 1,000 步按死亡优先、再食物判胜；双方终止且没有 bootstrap |
| 对手冻结 | 对手参数/哈希在本局和学习者更新后不变；独立循环记忆每局清空 |
| 重置与随机源 | 同版本、同种子与同动作序列能重现；不同种子是否真的改变食物/世界须实际检查 |
| 空间与数值 | 观测 shape、dtype 和范围一致；奖励有限；动作均能被后端处理 |
| 终止目标 | 真正终止时 TD 目标等于即时奖励；截断时仍包含后续价值 |
| 网络更新 | 一次更新会改变在线参数；同步前目标网络不变；目标网络没有梯度 |
| 经验池 | 保存观测副本，环境后续原地修改数组不会改写历史样本 |
| 存档恢复 | 同一模型加载前后对同一输入给出相同输出；随机策略用相同 RNG 状态比较 |
| 奖励事件 | 连续触发、重复拾取、位置往返不会绕过既定奖励规则 |
| 多阶段流程 | 技能切换保留世界、背包和计时；失败/超时能返回调度器 |

可使用 Gymnasium 与所用算法库的环境检查器，但检查器通过不等于游戏逻辑正确。环境 API 检查、人工查看短轨迹和精确规则案例应结合使用。[SB3 自定义环境说明](https://stable-baselines3.readthedocs.io/en/master/guide/custom_env.html)

建议按以下顺序诊断训练失败：先看随机动作录像和奖励分量；再确认采样、网络更新和 TD 目标；然后检查探索覆盖与观测；最后才调整超参数、增加网络规模或训练预算。loss 下降不能单独证明游戏能力提高。

### 4.4 图像与数据处理

图像包装器顺序、裁剪范围、通道顺序、帧堆叠、动作重复、奖励缩放及归一化须写入配置快照。重置后堆叠帧不得混入上一局，训练与评估应复用同一预处理。

避免重复归一化：如果框架已将 `uint8` 图像除以 255，输入端不要再做同样处理；使用自定义浮点图像时核对策略库设置。回放池优先以紧凑格式保存图像，训练采样后再转换；优化存储时仍需保持转移和帧边界正确。

有运行统计的观测归一化器只在训练中更新，验证与测试加载并冻结训练统计。奖励归一化或裁剪只用于训练目标，原生分数和原始成功事件必须保留。

### 4.5 日志、模型与复现清单

每次运行建立唯一 `run_id`，记录代码提交号或源码哈希、配置哈希、环境/游戏版本、依赖清单、算法初始化种子、环境种子列表、动作权限、辅助资源、训练步数、梯度更新次数、底层帧/tick 数、墙钟耗时、硬件型号和峰值显存。

模型文件至少包含网络参数、观测/动作配置及训练归一化统计。可恢复训练状态还应保存优化器、目标网络、步数、探索日程、RNG 状态；DQN 需说明是否保存回放池。若无法恢复模拟器完整状态，从新回合继续并记录断点，不声称位级精确复现。

同时保留“验证最优模型”和“末次训练模型”。使用独立验证环境，不让验证改变训练环境、探索 RNG 或统计量。单蛇按验证平均食物数选模型；双蛇按固定随机/启发式验证对手等权平均的对局得分率选模型；马里奥先按验证通关率、再按平均最远距离；Minecraft 按登记的主任务成功率。并列时选较早模型。测试结果不得用于选择 checkpoint。

## 5. 算力、兼容性与八周安排

### 5.1 PC 与 DGX 使用建议

| 场景 | 建议安排 | 先测量什么 |
| --- | --- | --- |
| 贪吃蛇小型 MLP | CPU 或单 GPU 均可，先比较实际速度 | Python 环境步进、数据复制和 batch 更新耗时 |
| 双蛇自博弈 | 先单学习者对冻结对手，再增加并行环境 | 联合步吞吐、对手推理、快照加载和历史池内存 |
| 马里奥视觉训练 | 单 GPU 起步，逐步增加 CPU 环境进程 | 每秒总决策数、模拟器占用、图像传输与 GPU 利用率 |
| Minecraft | 先启动一个稳定实例，再尝试多个环境 | 实例启动/重置时间、CPU/RAM、渲染资源和服务器稳定性 |
| DGX 多 GPU | 优先把不同训练种子/消融分配到不同作业 | 每个任务的 CPU、RAM、GPU 与存储限制 |

使用 DGX 不意味着单个游戏实例自动加速；默认不要求分布式训练。先完成单卡基线，再考虑多 GPU 梯度同步。按课程平台调度方式申请资源，显式设置进程数和 GPU，避免每个实验都占用全部设备。DGX 的具体 GPU 型号、架构和配额由实际分配决定，报告中填写实测信息。

建议三款游戏使用独立软件环境。先查看所选版本的安装说明，再确定 Python、PyTorch、驱动、原生编译依赖和 Java/显示组件。个人 Windows 环境、WSL2 与 Linux 服务端的兼容性须分别验证；无显示服务器时，先核对后端是否支持所需的离屏渲染方式。本文不提供未经本机验证的统一安装命令或固定版本组合。

### 5.2 预算估算与降级路径

第一周对单蛇和马里奥在目标平台完成（双蛇原型完成后补测，MC 选做时补测）：随机策略不少于 1,000 个决策步，跨至少 3 次重置；随后跑 10–30 分钟小规模训练，记录包含参数更新的实际吞吐、重置耗时、峰值显存与 RAM。排除模型初始化后，再统计稳定阶段吞吐。

若实测含训练开销的总吞吐为 $F$ 个环境决策/秒、计划累计训练 $N$ 步，可粗估：

$$
\text{训练时长}\approx N/F,
\qquad
\text{总预算}=\text{训练}+\text{验证与测试}+\text{启动重置}+\text{排队及故障余量}.
$$

这是容量估计，不能由吞吐反推必然学会某项技能。并行环境的 $N$ 按所有环境步数之和计，动作重复另外累计底层帧。双蛇一次双方同时行动算 1 个联合环境步，并另外报告 2 个 agent 动作；保存两方样本不等于交互量翻倍。每项主要方法至少 3 个种子，预算规划应先乘上种子数和实验配置数，并为验证、测试和重跑预留约 30% 的时间。

若第 1 周马里奥启动困难，先降为单实例并定位依赖。若第 3 周学习信号仍不明确，先排查规则、奖励和接口，再降低训练场景复杂度；正式评测保留既定任务及视觉权限。MC 启动困难时可更换已声明后端或只做基础阶段，不挤占必做项目预算。不能删除失败测试或省略独立种子制造达标结论。基础协议确需改变，应在正式测试前登记，由教师按同一学习目标确认。

## 6. 实验协议与结果模板

### 6.1 训练、验证与测试拆分

训练集用于采样与更新，验证集用于选择超参数和模型，测试集只用于最终评估。第 2 周提交单蛇与马里奥拆分清单，第 4 周前补齐双蛇对手协议，MC 启动时登记阶段清单；测试种子可以公开固定，但禁止因测试表现更改策略。若误用测试进行调参，该集合应改称验证集并另建未使用的测试集合。

| 游戏 | 训练 / 验证划分 | 必须报告的最终测试 |
| --- | --- | --- |
| 单蛇 | 不重合的食物随机种子列表；相同基础规则 | 未见食物序列；扩展地图单列 |
| 双蛇 | 训练对手池、固定验证对手与种子；测试对手隔离 | 随机/启发式/其他种子冻结模型，交换座位；历史对手另列 |
| 马里奥 | `1-1` 学习；独立起始条件验证 | `1-1` 保留起始条件 + 未见 `1-2`、`1-3`，逐关列出 |
| Minecraft（选做） | 不重合的世界种子、场景/存档标识和初始化清单 | 子任务与连续组合的未见场景；辅助起点及完整流程另列 |

训练种子控制网络初始化、探索及采样顺序，环境种子控制食物/世界等变化；两者不可混称。推荐算法训练种子采用 `0, 1, 2`，环境拆分清单独立维护。贪吃蛇可采用训练 `0–999`、验证 `1000–1019`、测试 `10000–10019`；每个回合按对应列表和 RNG 日程选种子并记录。不同方法采用同一测试清单，方便配对比较。

### 6.2 最小实验矩阵

| 部分 | 必须包含的配置 | 重复要求 |
| --- | --- | --- |
| 单蛇 | 随机、启发式、DQN、至少一个改进 | 主要可训练方法各至少 3 个训练种子；每模型每测试条件至少 20 局 |
| 双蛇 | 历史池自博弈，以及固定对手训练或仅最新快照的受控对照 | 主要可训练方案各至少 3 个训练种子；每模型每对手 20 个环境种子 × 2 个座位 = 40 局 |
| 马里奥 | 随机、RL 基线、最终方案、两项关键消融 | 基线和最终方案各至少 3 个训练种子；每模型每测试关卡至少 20 局 |
| Minecraft（选做） | 每个申请阶段的未学习/未微调对照、RL 方案及贡献分析；共享策略可复用训练运行 | 主要学习方案至少 3 个训练种子；短任务每模型每条件至少 20 局，长阶段/组合至少 10 次 |

双蛇最终对手包含随机、启发式和本组其他独立训练种子的最终冻结策略。例如模型 A0 对随机、启发式、A1、A2 分别评估，每个对手至少 40 局。主要受控方案按相同对手清单比较；必要时将所有主要方案最终策略形成冻结对手合集，评价时去掉自身，并逐对手报告，避免不等难度对手平均值误导。

同一对策略、同一环境种子与座位的对局可在完整交叉矩阵中共用一条原始记录，双方胜负互为镜像，不重复计为独立比赛。每个种子完成两种座位分配；它们是配对条件，不是两个独立训练。训练/调参阶段不得使用其他训练种子的最终模型；它们只在模型锁定后交换作组内最终评测。随机与启发式可用于训练或验证，但最终食物种子应保留，结果称为“固定对手未见场景表现”，不声称对手本身未见。

历史快照可能已经出现在训练池，单独绘制遗忘矩阵。比较跨种子冻结对手时给出逐对手和逐座位结果；不因比赛优势形成传递排序，不输出 Elo 或班级榜单。

消融原则上沿用 3 个训练种子；资源不足可先用 1 个种子探索，但只能标注为探索性证据，不能声称稳健结论。固定随机/启发式与未微调模型不伪造训练种子，记录评估随机源即可。3 个模型各测试 20 局不等于 60 次独立训练；MC 长任务为 3×10，只有单次成功录像的成果标为个案演示。

所有比较对齐观测权限、动作、规则和预算。主方法尽量使用相同环境交互预算，同时报告墙钟时间；额外预训练、示范、技能或大模型成本单列。MC 不强制为每个新材料支线另训三个模型；同一冻结策略可评估多个登记目标，但每项申请计分的目标必须有对应评测与学习贡献证据。

### 6.3 改进、消融与 RL 贡献如何验证

单蛇至少一项改进对照，双蛇至少一项对手机制对照，马里奥至少两项关键消融；同一受控实验可同时满足改进与消融要求。MC 至少提供作用于申请阶段的 RL 贡献对照，不因每增加一个材料支线额外强制两项消融。

马里奥的两项消融必须针对两个明确机制，而不是两次随意改学习率。例如：马里奥最终方案使用课程学习和奖励塑形，分别去除课程、去除塑形；Minecraft 最终方案使用预训练初始化和高层技能调度，分别比较从随机初始化训练、固定调度与学习调度。观察权限增加属于信息条件改变，要标注为权限对照，不归因于算法本身。

至少一个对照必须直接检验 RL 贡献：相同初始权重、辅助资源、技能库和推理权限下，对比不做 RL 更新与进行 RL 更新。若预训练模型已完成大部分任务，应解释 RL 改善的是成功率、效率还是泛化；效果没有改善也必须如实报告。

方法未包含两个可去除的模块时，可选择两个有清晰假设的机制对照，例如不同折扣范围、是否使用历史观测或不同探索机制。改变历史观测会改变可用信息，须单列说明。每项实验先写“假设—唯一主要变化—预期观察—实际结论”。

### 6.4 统计与异常处理

每个训练种子先计算其测试局均值，再对种子均值报告平均值与样本标准差；成功率同时列出每个模型的成功次数/总次数。只有 3 个种子时避免强显著性宣称。可补充中位数、四分位数或置信区间，但应说明统计单位与方法，不能将同一模型多局当作独立训练来缩小误差条。

训练曲线以累计环境步为主要横轴，同时提供墙钟耗时。跨种子均值曲线使用一致评估步点，阴影定义为跨种子标准差或明确说明的区间。保留原始数据，平滑曲线注明窗口，不能只展示最好的一条曲线。

成功用时只在成功局上统计，并列出成功数量；失败局包括超时，不能从成功率分母删除。日志中的基础设施异常单独标记，保留失败尝试和重跑记录，按原定种子重跑，不得只挑成功替代。由策略正常动作造成的死亡、卡住或预算耗尽均是任务失败，不算基础设施异常。

| 双蛇 | 环境与接口 | 4 | 同步碰撞/胜负/时限正确 2；观测对称与策略协议 2 |
| 双蛇 | 自博弈实现 | 7 | 对冻结对手实际学习 3；快照与历史池 2；采样记录与预算 2 |
| 双蛇 | 对照与分析 | 5 | 对手机制消融 2；非平稳/遗忘分析 2；解释逐对手差异或策略循环 1 |
| 双蛇 | 对战评估与效果 | 4 | 规定对手、种子、座位及矩阵齐全 2；学习增益与未见对手表现 2 |
| 马里奥 | 建模与视觉流程 | 5 | 图像/动作设计 3；奖励/终止与权限 2 |
| 马里奥 | RL 与自主改造 | 9 | 实际训练与原理解释 4；自主模块及受控贡献证据 5 |
| 马里奥 | 闯关表现 | 6 | 独立测试推进能力 3；通关能力、重复评测与用时证据 3 |
| 马里奥 | 泛化评估 | 4 | 预登记未见关卡评测 2；泛化效果与边界分析 2 |
| 马里奥 | 两项消融 | 6 | 每项假设、受控实现、结果解释各 1，两项共 6 |
| 报告答辩 | 综合报告 | 10 | 公平拆分与多种子统计 3；失败分析 2；图表表达 2；可追溯引用与复现说明 3 |
| 报告答辩 | 个人答辩 | 10 | 单蛇核心原理 3；双蛇博弈与马里奥视觉流程各 2；解释一个实验 3 |
| 过程协作 | 过程管理 | 5 | 八周里程碑与配置/日志记录 3；模型加载与独立评估复现 2 |
| 过程协作 | 个人贡献 | 5 | 可追溯成果与组内交叉确认 3；协作交接与共同理解 2 |
| **合计** | **单蛇 20＋双蛇 20＋马里奥 30＋报告答辩 20＋过程协作 10** | **100** | **Minecraft 附加分另计，最多 20** |

单蛇、双蛇、马里奥、综合报告和过程管理共 85 分为小组公共部分；个人答辩 10 分与个人贡献 5 分按个人评定。MC 以小组通过验收的阶段分计入各成员，个人是否理解其参与部分可在既有答辩中核查，不增加新的基础分项目。

每个实现/分析子项按正确性和可核对证据评分：完整正确得满分，部分完成按证据给部分分，未完成或关键结论错误不得对应分。效果子项无有效成果证据得 0，少量条件或不稳定改善得该子项一半，多个训练种子与预登记测试支持对应能力得满分；可保留 0.5 分。不存在未经课程基线验证的“平均食物数必须 20”门槛。

马里奥稳定通关 1-1 是主要目标，未通关仍可获得实现、推进、泛化评测和分析对应分，通关效果子项据实给分。双蛇战绩只占上述少量效果分，不能替代训练过程与博弈分析，不按跨组名次给分。

MC 阶段分严格使用第 2.3 节九阶段表：P1/P2 正常档各 1 分，辅助档各最多 0.5 分；T1–T7 按辅助档 50% 或完整档 100%，同阶段只取最高分。黄金器、钻石器、附魔等额外支线不新增分值，也不能借“创新”再次增加基础成绩。育人意义通过自愿探索、真实记录与反思体现，不成为装备数量竞赛。

对无效改进可凭正确实现、充分对照和诚实分析获得方法与分析分，不得包装成正向成果来获取效果分。只交视频缺少可复现模型或规定统计，不能替代对应证据。

### 7.3 学生实验报告提纲

1. 摘要：研究问题、任务范围、主要结果与边界。
2. 任务建模：状态/观测、动作、奖励、终止、信息权限与长期决策难点。
3. 环境与工程：版本、接口、预处理、规则检查、随机性和算力。
4. 算法：手写 DQN、自博弈与历史池、视觉策略、自主改造、引用与本人贡献。
5. 实验设计：基线、消融、预算、拆分、独立种子和统计方法。
6. 结果：训练曲线、单蛇指标、双蛇矩阵、马里奥通关与泛化、消融和资源消耗；MC 选做阶段另列。
7. 失败分析：至少两类失败轨迹及对应机制解释。
8. 局限与后续：已证明什么、尚未证明什么；选做 MC 时分析长链瓶颈与自主探索反思，不用装备数量代替创新。
9. 复现说明、贡献分工与参考资料。

### 7.4 答辩问题示例

1. 指出代码中 TD 目标、停止梯度和目标网络同步的位置，并解释各自作用。
2. 同一状态撞墙终止与时间预算截断，目标值为什么可能不同？
3. 智能体拒绝吃食物而循环行走时，你如何区分奖励问题、探索问题与代码问题？
4. 你提供的观测是否满足 Markov 性？马里奥单帧缺少什么信息？
5. 为什么不能用训练回报比较两个不同奖励设计？
6. 三个训练种子各测试 20 局，与训练一个模型测试 60 局有什么不同？
7. PPO 和 DQN 对旧数据的使用有什么差别？你选择当前算法的原因是什么？
8. 移除预训练、RL 更新或高层规划，哪个部分的能力会消失？证据在哪里？
9. Minecraft 子任务成功但组合失败，可能是哪些状态分布变化造成的？
10. 若硬件预算减半，你会保留哪些实验以保证结论可信？
11. 双蛇同时进入同一食物格、交换头位置和第 1,000 步时，代码如何统一结算？
12. 为什么战胜最新对手不一定代表更强？历史池与未见种子对手分别检验什么？
13. 选择黄金器或钻石器路线的动机、成本和用途是什么？哪些结果否定了最初假设？

### 8.5 课程设计参考

本版课程结构参考教师提供的《强化学习大作业任务书—游戏 AI 挑战》：吸收两款必做、双蛇自博弈与 MC 分阶段验收的设计。具体采用本任务书的 3–5 人、8 周、组内冻结对手评测和九阶段计分；开放科技树支线不额外加分。引用该材料不代表照搬其中的成绩门槛、比赛安排或算法适用性判断。
